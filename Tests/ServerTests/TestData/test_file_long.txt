Retrieval-augmented generation (RAG) is a technique that enables large language models (LLMs) to retrieve and incorporate new information. With RAG, LLMs do not respond to user queries until they refer to a specified set of documents. These documents supplement information from the LLM's pre-existing training data. This allows LLMs to use domain-specific and updated information that is not available in the training data. For example, this helps LLM-based chatbots access internal company data or generate responses based on authoritative sources.

RAG improves large language models by incorporating information retrieval before generating responses. Unlike traditional LLMs that rely on static training data, RAG pulls relevant text from databases, uploaded documents, or web sources. According to Ars Technica, RAG is a way of improving LLM performance by blending the LLM process with a web search or other document look-up process to help LLMs stick to the facts. This method helps reduce AI hallucinations, which have caused chatbots to describe policies that don’t exist or recommend nonexistent legal cases.

RAG also reduces the need to retrain LLMs with new data, saving on computational and financial costs. Beyond efficiency gains, RAG also allows LLMs to include sources in their responses so users can verify the cited information. This provides greater transparency, as users can cross-check retrieved content for accuracy and relevance. The term RAG was first introduced in a 2020 research paper from Meta.

### RAG and LLM Limitations

LLMs can still provide incorrect information. For example, when Google first demonstrated its LLM tool "Google Bard," the model provided incorrect information about the James Webb Space Telescope. This mistake contributed to a \$100 billion decline in the company’s stock value. RAG reduces such errors but does not eliminate them. For instance, LLMs can generate misinformation even when pulling from factually correct sources if they misinterpret the context. One example is an AI-generated statement claiming that the United States had a Muslim president, retrieved from a book with a rhetorical title, which the model misinterpreted.

Another limitation is "prompt stuffing," where extra relevant context is added to the user’s input to guide the model’s response. This helps prioritize new information over training knowledge but introduces complexity.

### Process

RAG enhances LLMs with an information-retrieval mechanism that allows them to access and use external data. AWS describes RAG as a way to retrieve relevant information from external sources to generate more accurate and contextually relevant responses. When a user submits a query, a document retriever searches for relevant content, which is then incorporated into the response. Ars Technica notes that instead of retraining the model when new information becomes available, RAG allows updating the external knowledge base. IBM adds that during the generative phase, the LLM synthesizes an answer using both the augmented prompt and its internal training.

#### Key Stages

* **Indexing:** Data is converted into embeddings (numerical vector representations) and stored in a vector database. RAG can work with unstructured, semi-structured, or structured data, such as knowledge graphs.
* **Retrieval:** For each user query, the retriever selects the most relevant documents to augment the prompt.
* **Augmentation:** The retrieved information is fed into the LLM along with the query, often through prompt engineering. Newer implementations expand queries and use memory for self-improvement.
* **Generation:** The LLM produces an output based on both the original query and the retrieved documents. Extra steps, such as re-ranking, context selection, and fine-tuning, may be added.

### Improvements

Several enhancements exist for RAG:

* **Encoder improvements:** Optimizing embeddings with dense or sparse vectors, approximate nearest neighbor searches, or hybrid methods. Late Interactions refine document ranking.
* **Retriever-centric methods:** Pre-training retrievers, using diverse data augmentation, supervised optimization, or reranking retrieved results.
* **Language model integration:** Approaches like Retro, which redesign the LLM with retrieval in mind, reduce network size while maintaining quality, though with higher training costs.
* **Chunking strategies:** Splitting data into fixed-length overlapping chunks, syntax-based chunks, or format-aware chunks (e.g., code files, HTML, PDFs).
* **Knowledge graphs:** Representing information as structured graphs, which can improve retrieval relevance.
* **Hybrid search:** Combining vector search with traditional keyword search for more comprehensive results.

### Evaluation and Benchmarks

RAG systems are evaluated on both retrieval accuracy and generation quality. Common benchmarks include BEIR, Natural Questions, and domain-specific datasets such as LegalBench-RAG for legal document retrieval.

### Challenges

RAG improves accuracy but does not fully solve the problem of hallucinations. LLMs may still produce misleading or incorrect information, especially when sources are misinterpreted or conflicting. They may also merge outdated and updated facts in misleading ways. Another issue is that models sometimes fail to recognize their own knowledge limitations, generating answers even when uncertain.
